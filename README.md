# FGST-KEAGN

Core algorithm implementation for the two-stage forest-fire risk prediction framework: **FGAT-FS** feature selection and **LLM-KEAGN** knowledge-enhanced adaptive gating.

Repository maintainer: [yan-wenguang](https://github.com/yan-wenguang).

## Overview

Forest fire risk prediction is a critical prerequisite for disaster prevention and mitigation decision-making. However, most prediction methods suffer from severe correlation redundancy when handling high-dimensional multi-source features, and their feature weights are derived entirely from statistical fitting, lacking consistency with the physical mechanisms of fire occurrence, resulting in insufficient interpretability under dynamic risk conditions. To address these challenges, this paper proposes an interpretable forest fire risk prediction framework that integrates structural feature selection and large language model-driven knowledge enhancement. Specifically, the proposed framework first employs a feature graph attention network to adaptively quantify the structural synergy relationships among factors, enabling discriminative selection of key factors and redundancy elimination. Subsequently, a knowledge adaptation layer is designed to adaptively align the feature importance priors generated by the large language model with the local environmental state of the current sample, thereby endowing the model with physical attribution capability. Furthermore, a dynamic context-aware gating mechanism is introduced to dynamically adjust the weighting proportion between the data-driven branch and the knowledge-enhanced branch based on real-time environmental variables, allowing a dynamic balance between statistical evidence and physical priors. Experiments conducted on three independent datasets demonstrate that the proposed method achieves superior prediction performance compared with existing baseline models and maintains robust performance under noisy conditions. This study provides a reliable and interpretable intelligent technical pathway for early warning and precise prevention and control of forest fires.

## Algorithm implementation

- `src/graph/`: mutual-information, correlation and classification-synergy matrices, feature-node statistics, and redundancy-aware feature selection.
- `src/models/fgat_fs.py`: feature-graph attention, learned relation mixing, feature scoring and soft selection.
- `src/models/llm_keagn.py`: data and knowledge branches, context encoding, adaptive gating and prediction head.
- `src/losses/`: classification, sparsity, branch alignment and context smoothness losses.
- `src/knowledge/`: feature-card construction and a local JSON prior provider.
- `src/trainers/`: stage-one and stage-two training, validation checkpoint selection and output generation.
- `src/pipelines/`: standalone stages and a complete two-stage runner.

The current knowledge provider reads supplied local JSON priors. Missing priors use a feature-card/statistical fallback. The supplied implementation does not make an online LLM request. The name `LLM-KEAGN` follows the manuscript/module naming; it does not imply that an LLM service is called during execution.

## Installation

Run from the repository root using Python 3.10–3.12:

```bash
python3 -m venv .venv
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-core.txt
python -m pip install -e .
python -m pip check
```

The installable `fgst_keagn_support` package contains auxiliary utilities. Core algorithm modules use the `src.*` imports and are run from the repository root.

## Run the core algorithm

```bash
python -m src.pipelines.run_full_pipeline --config configs/core_demo.yaml
```

The public configuration runs both stages for three epochs on `examples/synthetic.csv`. It is a smoke demonstration of the actual models, not a paper benchmark. Outputs include selected features, metrics, weights and predictions under `artifacts/core_demo/`; generated outputs are ignored by Git.

To use your own numeric CSV, copy `configs/core_demo.yaml`, set `data.csv_path`, `data.label_column`, the context columns, training settings and knowledge paths. Labels must be 0/1 or -1/+1. Set the feature-selection bounds to match the available feature count. Keep at least one numeric context column. See [CORE_ALGORITHM.md](docs/CORE_ALGORITHM.md).

## Data

`examples/synthetic.csv` contains 240 independently generated rows with three input features, a context field and a binary target. [DATA.md](docs/DATA.md) describes its origin and schema. Five processed research CSV files are available in [`data/processed/`](data/processed/), including the primary 1,215-row input and four external-data variants. [RESEARCH_DATA.md](docs/RESEARCH_DATA.md) documents fields, checksums, label counts and source limitations. Raw inputs, study-specific prior files, trained checkpoints and the complete experiment archive remain outside this release.

Run the primary processed input with:

```bash
python -m src.pipelines.run_full_pipeline --config configs/processed_primary.yaml
```

The short public configurations verify execution and are not the final paper experiment settings.

## Tests and auxiliary example

```bash
python -m unittest discover -s tests -v
python -m examples.generate
python -m examples.run --config configs/synthetic_example.json
```

The logistic-regression example is separate from the two-stage core algorithm. [EVALUATION.md](docs/EVALUATION.md) documents the auxiliary evaluator; the original core evaluator uses its own metric conventions described in [CORE_ALGORITHM.md](docs/CORE_ALGORITHM.md). [VALIDATION.md](docs/VALIDATION.md) distinguishes historical supporting-package checks from core execution checks.
